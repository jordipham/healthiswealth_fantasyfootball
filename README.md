# Health is Wealth — Fantasy Football League Analytics Platform

A full-stack web application that turns 8 seasons of ESPN fantasy football league history
into an interactive site: historical records, head-to-head rivalries, draft recaps, and a
dedicated analytics section applying real statistical and ML methods (k-means clustering,
hypothesis testing, Monte Carlo simulation) to the league's own data.

Built end-to-end — Python ETL pipeline, vanilla JS/HTML/CSS frontend, no framework.

---

## Overview

This started as a way to turn a decade of league data sitting in ESPN's API into something
the league could actually browse — then grew into a real data engineering project: resolving
duplicate manager identities, handling a mid-history draft format change (snake → auction),
and applying statistical methods to answer questions like "how lucky was this championship,
really?" and "do preseason projections actually predict final standings?"

**[Live site link — add once deployed](https://jordipham.github.io/healthiswealth_fantasyfootball/)**

---

## Tech Stack

- **Backend:** Python (standard library + `espn_api` for ESPN data access, `networkx` for
  rivalry network analysis)
- **Frontend:** Vanilla JavaScript, HTML, CSS — no framework. Custom reusable Web Component
  for site-wide navigation.
- **Visualization:** [Chart.js](https://www.chartjs.org/) (analytics pages only)
- **Data format:** JSON, generated by a dependency-ordered pipeline of Python scripts

## Notable Engineering Decisions

A few things worth highlighting for anyone reading the code, not just the site:

- **Snake vs. auction draft era handling.** The league switched draft formats partway through
  its history. Rather than force one evaluation system onto both, every value-related
  statistic (best picks, steals, busts) is computed *separately* per era, since a round-based
  formula and a dollar-based formula aren't comparable numbers.
- **Dynamic, not hardcoded, statistical thresholds.** Rarity tiers and bid-value cutoffs are
  recalculated from the real data distribution on every pipeline run — not fixed numbers.
  This was a direct fix after discovering that excluding QBs from value rankings (see below)
  shifted the underlying distribution enough to make the old hardcoded cutoffs misleading.
- **QBs excluded from value/steal/bust rankings.** QBs are typically drafted late but score
  heavily due to how fantasy points are weighted, which structurally skews round-based or
  price-based "value" formulas regardless of actual draft skill. QBs get their own dedicated
  ranking instead.
- **Manual override files for judgment calls a script can't make safely** — e.g. resolving
  which co-owner on a team was the real decision-maker (ESPN's own API ordering isn't
  reliable for this), confirming each season's actual draft format. These live in version
  -controlled JSON config files with documented reasoning, not inferred silently.
- **Honest handling of irrecoverable data.** A player drafted, dropped, and never reclaimed
  by anyone has no recoverable stats from ESPN's API for that season — this is disclosed
  directly in the UI rather than silently hidden or guessed at.

## Data Pipeline

```
gofetch.py  (pulls raw data from ESPN's API)
    ↓
compute_*.py scripts  (6 independent transforms)
    ↓
rollup scripts  (combine the above into page-ready JSON)
    ↓
a_compute_*.py scripts  (analytics layer: clustering, simulation, hypothesis testing)
```

Full script-by-script run order and manual configuration file documentation is maintained in
`MAINTENANCE.md`.

---

## Known Limitations

- A player drafted and dropped without ever being picked up by anyone else that season has no
  recoverable stat line from ESPN's historical API — disclosed in-app, not hidden.
- Some statistical methods (manager clustering, certain hypothesis tests) are run against a
  small sample (15 managers, 8 seasons) and are explicitly labeled "illustrative, not
  statistically robust" on the site itself.
- No automated test suite — correctness was validated by testing each script against real
  data and checking outputs by hand (including catching and fixing several real bugs this
  way) rather than a CI-integrated test suite.

## Setup

```bash
git clone https://github.com/jordipham/healthiswealth_fantasyfootball.git
cd healthiswealth_fantasyfootball
pip install espn_api python-dotenv networkx
```

Create a `.env` file with your own ESPN league credentials:
```
LEAGUE_ID=your_league_id
ESPN_S2=your_espn_s2_cookie
ESPN_SWID=your_swid_cookie
```

Then run the pipeline (see `MAINTENANCE.md` for the full ordered sequence):
```bash
cd scripts
python gofetch.py
# ...full sequence in MAINTENANCE.md
```

Open `index.html` via a local server (e.g. VS Code's Live Server extension) — the site uses
`fetch()` to load data, which requires `http://`, not `file://`.
